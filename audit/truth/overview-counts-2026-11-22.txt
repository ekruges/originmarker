Overview counts for a run
=========================

Plan item 3.9, rule C. The rule and its pass test are written here BEFORE the scoring run, copied
from the plan item with the decisions taken before the build. The results are appended under the
RESULTS line. Nothing above that line is edited after the run.

Cells are named by row index or not at all. No array is named in this file.

RULE C
------
One flat table for the run, built only from fields each record already has:
- samples by stage, and by reportable or not (no sample-level refusal; integrity.disturbed;
  integrity.uninterpretable);
- changes by kind: loss or gain, and whole, arm or piece;
- by parent: maternal, paternal, not named;
- embryos and units per embryo, where the page groups cells;
- origin per change, where rule B1 gives one.
"Arm" is a piece that starts within 5 Mb of the chromosome end or the centromere and ends within
5 Mb of the centromere or the other end. Findings (copy-neutral readings, complex) are counted on
their own line, not as losses or gains.

How the words in the rule are read in the code, fixed here before the run:
- A change is a row the result card counts (pageSays.changeList(...).counted), never a raw defect
  row. Its direction is gain for a gain row, loss for a row of a loss kind (copy-loss,
  parental-absence, monosomy, segmental-deletion). A counted row with no direction (copy-neutral
  readings, the uneven-shares reading) is a finding, and a genome too disturbed to reference
  against (complex) is one finding per sample. Rows the card lists as seen once, not confirmed,
  are counted on their own line and are not changes.
- Reportable classes come from the sample-level integrity refusal only: none is reportable,
  integrity.disturbed is limited, integrity.uninterpretable is not reportable. A sample not
  reportable is counted in the sample lines and contributes no change, finding or origin.
- Arm: a piece that runs from within 5 Mb of the chromosome's start to within 5 Mb of the
  centromere, or from within 5 Mb of the centromere to within 5 Mb of the chromosome's end. Every
  other piece is a piece. Centromeres and chromosome ends are the centromere and telomere rows of
  the gap table the tool ships (web/public/hg19_features.json); the tool ships no cytoband file.
- Embryos: groups of two or more units as the page forms them; a sample in no group is counted on
  its own line.
- Origin per change: the words the page prints for it (timing.ORIGIN_WORD), or no origin word.

PASS TEST (gate lines O1 to O6 of item 3.9)
-------------------------------------------
- O1. One flat table on the page and in the download, built only from the per-sample records:
  samples by stage, by reportable class; changes by direction and whole, arm or piece; by parent;
  embryos and units per embryo; origin per change.
- O2. Changes are counted as the result card counts them (pageSays.changeList rows), never as raw
  defect rows (raw rows overcount: 787 against 711 with a parent).
- O3. A check, sharing no code with the table, recounts every number from the records it
  summarises, and every number matches, on the 600 answer-key rows and the 271 lab rows. Run by
  exit code in scripts/checks.sh.
- O4. Classes sum to the totals; samples not reportable are counted and never contribute a change.
- O5. Flat style: no colour bands, no badges, no chart.
- O6. Browser run on a built copy; own version. Both are the landing's.

Scored on the records of the 330 answer-key rows with no parent, the 270 with a parent (each arm
its own run), and the 271 lab rows, with the embryo and origin lines read on today's grouping.

      (Overview TSV), built from per-sample records only: overviewSampleOf reads the card's
      change list, stage and sample refusals; overviewTable counts. Every line of rule C is in
      it, embryo and origin lines included.
  O2  holds. Changes are card rows (changeList(...).counted). Raw defect rows against card rows
      on the same records: lab 644 against 563, 330 rows 585 against 523, both parents 240
      against 121 counted plus 64 seen once.
  O3  holds. audit/truth/overview_check.py recounts every line from the records with no shared
      code and matches exactly on all seven runs and the synthetic fixture (35 to 38 lines each,
      0 mismatches), run by exit code from scripts/checks.sh (OM_OVERVIEW_DIR for real runs). A
      wrong number fails it (tested). checks.sh calls `node`; on tesla /opt/node22/bin must be on
      PATH or the step fails, as it should.
  O4  holds. Stage lines, reportable classes, losses plus gains, extent, parent, embryo and origin
      lines each sum to their totals in every run (checked by overview_check.py). Samples not
      reportable are counted and contribute no change.
  O5  holds. A plain bordered table of label and count; no colour band, badge or chart; no em
      dash in any label (overview.check.ts).
  O6  the landing's: a browser run on a built copy, and the version.
