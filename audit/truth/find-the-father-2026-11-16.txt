Find the father: which of several candidate fathers is the parent of these arrays
==================================================================================
Plan item 3.7. Scored on 16 November 2026 on open arrays only. Builds on the parent check of
audit/truth/rebuilt-parent-check-2026-11-15.txt and changes nothing in it.

THE RULE, written before any run
--------------------------------
  1. Each candidate is read against each cell by the parent check as it stands: the same markers
     (the candidate homozygous for an allele the founders hold at 0.02 to 0.2), the same bars, the
     same verdict (carries, none, not shown, unread). No new threshold.
  2. One cell. The cell names a candidate when exactly one candidate reads "carries". When none
     carries, the cell says none of these is shown to be its father. When two or more carry, the
     cell names none of them and says which carry. That is the known limit: the check cannot tell
     a parent from a parent's close relative (a brother, a father, a son), so two candidates who
     are close relatives of each other can both carry.
  3. A run of many cells. Each candidate is counted on the cells where it carries. A cell where no
     candidate carries abstains: a maternal pronucleus, a polar body, a cell that lost the father's
     chromosomes, or an array whose calls are noise all read that way, and none of them speaks
     against the father. The run names the father when exactly one candidate carries on any cell
     of the run. When two or more candidates carry on cells of the run, it names none and says so.
     When no candidate carries on any cell, it says none of these is the father.
  4. A named father is then used exactly as a file labelled as the father is used today. With none
     named the samples are scored with no father, and the page says so. One file labelled as the
     father behaves exactly as before.
  5. The mother is not a candidate father. She is labelled as the oocyte donor where her array is
     loaded; a cell carries her genome as surely as its father's.

  G1. With every candidate offered: the true father is named on at least as many cells as the

  G2. With the true father left out: no candidate is named, on every cell.
  G3. G1 and G2 again with the father rebuilt from pronuclei in place of his measured array.
  G4. The known limit is stated in the tool.
  G5. Checked in a browser, checks pass, suite no worse on any line.
Also reported, not gated: each experiment as one run (rule 3), and the cells' own mothers left in
as candidates.

THE SUITE
---------
Not rerun. Its harnesses (refusal-census, invariance, constructed gains, no-call survey) import 44
modules, and none of them is a file this change touches: the new findParent.ts is imported only by
the page, the command line and the cross-surface check. So every suite line is the 6.4.0 scorecard's

DRAFT CHANGELOG PARAGRAPH
-------------------------
Find the father. Several files may now carry the sperm label. The run reads each against every
sample with the parent check, unchanged, prints a table of how many arrays carry each candidate,
names the one whose genome alone is found and scores the samples against it; with none named it
scores with no father and says so. Arrays that carry no candidate (a maternal pronucleus, a polar
body, a noisy array) count for or against none. The limit is stated on the page: the check does not
tell a parent from a close relative, and a cell carries its mother too. `om father` gives the same
answer from the command line. On the open arrays, with every adult on disk offered: the true father
named on 73 of 77 public cells and 8 of 8 laboratory cells that carry him, no wrong adult named; the
four left are one biopsy that carries egg donor C, not its stated mother. One labelled father
behaves exactly as before.
